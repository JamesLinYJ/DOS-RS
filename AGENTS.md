# Working on DOS-RS

Start from the boundary that owns the state you need to change. The i686 and x86_64 targets use the same guest, scheduler, filesystem and device services.

| Owner | Code | Contract |
| --- | --- | --- |
| Boot | [UEFI entry](src/boot.rs), [BIOS loader](boot/bios/src/bin/loader.rs), [legacy handoff](src/boot/legacy.rs) | Validate memory ranges, stage the kernel, finish firmware calls and publish topology. The PE used by UEFI also exports the BIOS entry. |
| CPU and bus | [Architecture](src/arch.rs), [platform](src/platform.rs), [PCI](src/platform/pci.rs) | Own descriptors, AP initialization, hardware ports, PCI resource claiming, MMIO and DMA lifetimes. Keep physical access here or in the display backend. |
| Native drivers | [PCI registry](src/drivers.rs), [USB enumeration](src/drivers/usb.rs) | Register a PCI match and attach function. Implement USB class protocols against UsbIo. Keep xHCI descriptors, endpoint recovery and rings in the controller implementation. |
| Execution | [Kernel scheduler](src/tasks.rs), [DOS execution](src/guest/run/runtime.rs), [interpreter](src/guest/step.rs) | Only the assigned thread executes its slice. Return to the boot CPU for events, system calls and I/O. A waiting or faulted guest leaves other terminals runnable. |
| Guest CPU | [Registers and translation](src/guest/pc386.rs), [system instructions](src/guest/step/system.rs), [wide operands](src/guest/step/operand32.rs) | Extend the in-tree interpreter. Decode with the guest register file, translate selectors on every fetch or memory operand and route port operations to the session. Keep CR3, descriptor tables and virtual-8086 state with the saved CPU context. Translate DOS buffers and EXEC writes through the current V86 page tables. Preserve the guest VMM’s ability to trap PIC EOI and interrupt return. The guest module forbids unsafe Rust. |
| Guest memory | [Address space](src/guest/memory.rs), [XMS](src/dos_memory/xms.rs), [EMS](src/dos_memory/ems.rs) | Keep A20, handle state and page frames per session. XMS and EMS charge a single extended-memory allocator. DOS and XMS upper blocks share the paragraph arena, which reserves space for every visible MCB and the EMS frame. Validate maps before publishing them. Every access through an EMS alias must see the same bytes. |
| Processes | [Loader](src/guest/process.rs), [DOS services](src/guest/run.rs), [handles](src/guest/run/handles.rs), [termination vectors](src/guest/run/termination.rs) | Return to the address in the guest PSP. Publish MCBs and each PSP's JFT. DUP and inheritance share the open description and seek position. Release the child's references on return. |
| Native processes | [Pipeline launch](src/posix.rs), [descriptors](src/posix/io.rs), [native program API](native-posix/src/lib.rs) | Spawn each pipeline stage with its own PID and inherited descriptor table. Suspend only the caller on blocked I/O. Release every pipe endpoint at exit. Each child inherits a directory snapshot. Route path operations through the VFS. Keep application code independent of the disk and terminal drivers. Validate ELF images and user buffers in safe Rust. Only src/arch/user owns the BSP user page tables, privilege transition and timer trap. Keep C stubs and kernel syscall dispatch synchronized through native-exec/libc/syscalls.def. |
| Storage | [Open files](src/vfs.rs), [mounted volume](src/vfs/driver.rs), [DOS paths](src/vfs/dos.rs), [block devices](storage/block/src/lib.rs) | Route Shell, INT 21h, FCB, executable loading and native processes through the mounted volume. Both descriptor APIs retain an object independent of its directory name. Keep physical BIOS sector reads in the device layer. |
| Filesystem drivers | [FAT](src/vfs/fat.rs), [Btrfs](src/vfs/btrfs.rs), [NTFS](src/vfs/ntfs.rs) | Implement the Volume and Node interfaces. Keep format-specific metadata and transactions in the driver. The mount selects the first supported data volume as C. Filesystem I/O stays inside the partition bounds. NTFS only receives the BlockRead interface in its on-disk parser. |
| Display | [Terminals](src/bios/pc.rs), [renderer](src/bios/screen.rs), [guest VGA](src/guest/vga.rs), [guest AT input](src/guest/at.rs), [guest BIOS](src/guest/run/bios.rs) | A terminal owns its cells, attribute, cursor and key queue. Render the foreground terminal. Preserve DOS-supplied character attributes. |

Record the executing kernel in each acceptance result: native 16-bit DOS (286/386), 32-bit i686 or 64-bit x86_64. The CPU model of the emulator is a separate field.

## Native 16-bit target

The `dos` package selects `src/realmode.rs` on targets with 16-bit pointers. The resident IO.SYS in `boot/realmode` probes the CPU, loads the selected image from MSDOS.SYS and owns firmware access, console, storage and optical media. Keep FAT geometry and file positions in 32-bit units. The kernel owns PSPs, live per-process JFTs, MCBs, DOS services and EXEC. IO.SYS applies CONFIG.SYS. The first COMMAND.COM runs AUTOEXEC.BAT. Keep prompts, command lookup, built-ins and batch execution in `native-tools/src/command`. Both the initial interpreter and COMMAND.COM /C are DOS processes. Compare commands with MS-DOS 6.22 using `scripts/realmode-command.py`. Run `scripts/realmode-shell.py` for nested EXEC, pipelines, environment inheritance and keyboard input. On single-drive installations use `scripts/realmode-command-media.py` to exercise release identification and streaming when the disk contents exceed available conventional memory.

The native CONFIG.SYS loader sends INIT to flat character drivers and reserves the resident extent. A successful zero-length INIT on a 286 must leave no 386 vectors installed. New DOSK entries use independent 32 KiB LZ4 blocks. Their offsets have bits 31 and 30 set and their expanded lengths are stored in paragraphs. Keep the whole kernel below the BIOS disk buffers and each compressed transfer within one segment. The loader also accepts the original byte-length formats.

The rust16 architecture adapter owns mode transitions, trap frames and DOS calling conventions. The [386 monitor](boot/emm386/src/main.rs) owns page tables, the IDT, the TSS and IRQ reflection. The native monitor and the wide kernels share the LIM and XMS services in [dos_memory](src/dos_memory). The native physical allocator must keep XMS KiB, EMS pages, UMB backing and VCPI frames disjoint. Test released-page zeroing, duplicate and cross-API frees, frame aliases and free-space accounting. DOS and XMS share the upper paragraph allocator. Keep all visible MCB headers outside client data.

Run [the memory acceptance suite](scripts/realmode-ems-test.py) with a RAM volume, Borland EMSTEST and the Jemm clients. Check DOSBox-X 386, the same disk on 286, 386 without DEVICE, and an installed QEMU C: cold boot. A VCPI acceptance run must enter protected mode, invoke the server there, and return to DOS. Run the dual-architecture smoke suite after changing shared services.

The optional two-floppy set has a release ID on each disk. Test a wrong disk, cancellation, a swap in one drive, cold boot and host-side readback. SETUP stages disk 2 in its own PSP allocation. Keep the configuration buffer outside the staged payload.

The native utilities are built with the same rust16 compiler. Partition inspection, file transfer, startup configuration and installer rendering have separate modules in `native-tools/src`. Edit uses a storage-independent gap buffer with a segmented DOS adapter. Use emulator key events for interaction tests. The pinned legacy DOS compatibility clients and their source revision are documented in [tests/fixtures/dos](tests/fixtures/dos/README.md).

For native EMM changes, run the installation and legacy CPU checks in `scripts/realmode-ems-test.py`. Run `scripts/realmode-high-memory.py` to compare the DOS client's high-page reads with QEMU physical memory. For changes to ELF virtual addresses use the native ELF tests on both architectures, including high page faults and pipeline data.

The native DOS kernel owns the PSP and MCB chain, including high-loading an MZ image when both allocation fields are zero. Resolve file handles through the live JFT pointer and count in the current PSP. The SFT owns the open position. The FAT driver identifies a file by its directory sector and slot. EXEC streams the load module and uses a separate sector for relocation records. Run [the file ownership regression](scripts/realmode-file-ownership.py) with `--toolchain`, `--image`, `--ram-dir` and `--proof`. It runs DOSBox-X 286 and QEMU with the native 386 kernel on FAT16 and FAT32 and compares each stopped disk to host-generated bytes. The host sector failure suite is `rustc +stable --edition 2024 --test tests/native_fat_file.rs -o target/native-fat-file-test && target/native-fat-file-test`.

Keep the conventional arena bound fixed across the Windows VMM handoff. Reserve GEMMIS snapshot space before exposing the XMS free list. Run [the native Windows test](scripts/realmode-win32.py) with an installed Chinese Windows 3.2 BIOS disk and a RAM volume. It runs the 16-bit kernel on both Pentium III and x86_64 QEMU machines, checks XMS, enters `WIN /3` and captures the Windows About box. Use the separate i686 BIOS and x86_64 UEFI kernel builds for wide-kernel acceptance.

Build with the rust16 revision pinned in the README. Use a RAM volume for all writable test images. Run the native FAT, installer and Edit scripts listed in the README. Retain serial logs, screenshots and host-side file comparisons with `--proof`. Use `rustc +stable --edition 2024 --test tests/edit_buffer.rs -o target/edit-buffer-test && target/edit-buffer-test` to exercise document offsets beyond 64 KiB on a wide host.

## Checking a change

Run `python3 scripts/prepare-cpu.py` before the first build. It verifies the upstream sources against the pinned manifests. The project-owned boot, kernel, scheduler and drivers are Rust. Keep compiler-generated instructions and pinned architecture-library sources distinct from project-owned files. Use Rust for new project-owned code and host-driven application tests.

- Use [qemu.py](scripts/qemu.py) to boot the interactive kernel. Test BIOS and UEFI with each supported architecture. Use [qemu-native-gate.py](scripts/qemu-native-gate.py) to test the actual native INT 21h gate with both carry inputs, write a FAT file and read three records from an explicit C-drive FCB. Pass `--ram-dir` for the writable disks.
- Use [qemu-smoke.sh](scripts/qemu-smoke.sh) for host layout checks, [guest CPU and device tests](tests/pc386.rs) and DOS program regressions. The kernel-selftest build installs [its AUTOEXEC.BAT](tests/fixtures/AUTOEXEC.BAT) in a private copy of the shell volume. Each emulator must exit with status 33 and print `GUEST ARCH OK`. Record output with `PROOF_DIR`. Run `scripts/qemu-smoke.sh --pc386` to repeat the same DOS workloads with the protected-mode build.
- Run `python3 scripts/qemu-posix.py --ram-dir /path/to/ramdisk` for native streaming, unlink, descriptor lifetime and a DOS program on another terminal. The script checks redirected bytes on the stopped VM’s FAT disk.
- Run `python3 scripts/qemu-native-elf.py --ram-dir /path/to/ramdisk` for independently compiled ELF32/ELF64 pipelines, descriptor lifetime, memory limits, fault isolation and timer preemption. Verify stopped-disk bytes as well as serial output. The loader host tests use both ELF cross compilers and run with `cargo +stable test --locked --manifest-path native-exec/Cargo.toml`.
- Run the POSIX regression with `--fat 12 --fat 16 --fat 32` for a dosfstools check on each volume. Use [qemu-btrfs.py](scripts/qemu-btrfs.py) for DOS and native sharing, open-orphan recovery after power loss and validation with Linux btrfs-progs. Use [qemu-ntfs.py](scripts/qemu-ntfs.py) for NTFS raw/MBR/GPT reads, DOS EXEC and whole-image write protection. All three scripts take `--ram-dir` and `--proof`.
- Use [qemu-terminals.py](scripts/qemu-terminals.py) for background execution, multiple real CPU workers, keyboard blocking, fault isolation, private EMS frames, shared files and color screenshots. Set `--firmware bios` for the legacy path.
- Use [qemu-memory.py](scripts/qemu-memory.py) for XMS/EMS operations and add `--mem /path/to/MEM.EXE` for the FreeDOS client. Exercise both the default and `--extended-mib 128` to cover pool exhaustion and classic 16-bit query saturation. Use [qemu-devices.py](scripts/qemu-devices.py) for DOS drivers and PC peripherals. Use [qemu-hardware.py](scripts/qemu-hardware.py) for high-speed USB sector reads and Ethernet RX/TX.
- Windows 3.2 acceptance requires an installation on a writable DOS-RS volume, a cold boot and a working Chinese Program Manager. Boot with `--pc386 --c-disk <raw FAT volume>`. Verify the original text welcome screen, the Windows VGA driver in graphics mode and keyboard input. Reopen the same disk after exiting QEMU and capture the actual Program Manager screen. For enhanced mode, cold boot i686 BIOS and x86_64 UEFI with separate writable C disks on a RAM volume. Run `WIN /3`, open Help → About in each Program Manager and capture the 640×480 QEMU framebuffer after the mode text and resource counts appear. Keep original Microsoft installation media and personal disk images outside the repository.

The existing [translation inventory](checklist/v4.0.tsv) records upstream provenance. New DOS workloads belong in the [program notes](docs/guest-programs.md) with their inputs and observable results.
